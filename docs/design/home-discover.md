# Home · Discover 명세 v1

> 작성 2026-09-20 · 상태: 초안 (구현 전 확정본)
>
> **이 문서가 기준이다.** 프로토타입(`docs/prototype/home-discover-v1/`)은 레이아웃 참고용이며,
> 이 문서와 다르면 이 문서를 따른다. 프로토타입 이후 바뀐 결정이 있다
> (지역 칩 → 시트 제목, 카테고리 칩 이름, 태그 구조 등).
>
> 분류(장소 타입·태그) 기준은 `docs/design/taxonomy.md` 를 본다.

---

## 1. 원칙

| | 홈 | discover |
|---|---|---|
| 답하는 질문 | **무엇을** 볼까 (최애, 작품) | **어디로** 갈까 (지금 보는 지역) |
| 콘텐츠를 묶는 기준 | 토픽 · 시간 | 지도 위치 |
| 콘텐츠가 바뀌는 계기 | 탭을 바꿀 때 | 지도를 움직일 때 |

- 같은 종류의 콘텐츠(리크리샷 등)가 양쪽에 나와도 **묶는 축이 다르면** 겹치지 않는다.
- **홈 → discover** 는 필터를 들고 간다 (토픽 · 지역 · 카테고리).
- **discover → 홈** 은 결과 모드의 "Stories on Home" 링크로 연다.
- **개인화는 눈에 보이는 칩으로만** 한다. 필터가 없는데 몰래 정렬을 치우치게 하지 않는다.

## 2. 라우팅

| 경로 | 화면 |
|---|---|
| `/` | `/feed` 로 리다이렉트 (홈이 첫 화면) |
| `/feed` | 홈 · Hot 탭 |
| `/feed?tab=<topic-slug>` | 홈 · 토픽 탭 (L2 토픽만) |
| `/discover` | 지도 |
| `/topics/<slug>` | `/feed?tab=<slug>` 로 리다이렉트 (L2). 옛 링크 보존용 |

- 경로 이름(`/feed`, `/discover`)은 바꾸지 않는다 (`revalidatePath` 다수).
- 하단 내비: 홈 = `/feed`, 지도 = `/discover`.

## 3. 홈

### 3.1 상단

```
[검색바]
[ Hot | 구독 토픽 … | + ]   ← 가로 스크롤
```

- **Hot** 은 맨 앞 고정.
- **구독 토픽**은 사용자가 정한 순서대로. L2 토픽(그룹·작품)만 구독 가능. 멤버(L3)는 구독 대상이 아니다.
- **+** 는 구독 관리 시트를 연다.
- 선택한 탭은 URL 에 남긴다 (`?tab=`).
- **비로그인**: `[ Hot | + ]` 만. + 를 누르면 로그인 유도 시트
  ("Pin your favorite artists and shows") → 로그인 후 돌아오면 구독 관리 시트가 열린 상태.

### 3.2 Hot 탭 (위에서부터)

| # | 섹션 | 데이터 | 비고 |
|---|---|---|---|
| 1 | 배너 캐러셀 | HomeBanner | 이벤트 홍보도 여기로 |
| 2 | 한반도 지도 카드 "Where fans are going" | 시도별 장소 수 | 카드 → discover(필터 없음). 아래 지역 칩 → discover 그 지역으로 이동 |
| 3 | New from your topics | 구독 토픽의 최신 장소 포스트 | 로그인 + 구독 있을 때만 |
| 4 | Top ReCreeshots this week | 리크리샷 인기 정렬 | 비면 CTA (5.2 참고) |
| 5 | 큐레이션 섹션들 | CuratedSection (showOnHome) | 기존 그대로 |
| 6 | Journeys | 공개 Course | `[MOCK]` 제외 |
| 7 | Fresh Drops | 최신 장소 포스트 무한 스크롤 | 기존 그대로 |

- 기존 홈의 **이벤트 세로 캐러셀은 뺀다.** 이벤트는 위치 콘텐츠라 discover 로 간다.
  특별히 홍보할 이벤트는 HomeBanner 로 올린다.
- **한반도 지도 카드**: 지도 API 를 쓰지 않는다. 한반도 윤곽 SVG(빌드 전에 한 번 생성해 커밋) 위에
  시도별 핫스팟을 찍는다. 핫스팟 위치 = 그 시도 장소 좌표의 평균, 크기 = 장소 수.
  윤곽과 핫스팟은 같은 투영을 쓴다.

### 3.3 토픽 탭

| # | 섹션 | 비고 |
|---|---|---|
| 1 | 토픽 헤더 | 이름, 상위 카테고리(K-Pop 등), Following 토글 |
| 2 | 토픽 지도 카드 "BTS on the map" | → discover 결과 모드 (`?topics=bts`) |
| 3 | BTS ReCreeshots | |
| 4 | BTS Journeys | CourseTopic |
| 5 | 장소 포스트 피드 | Latest / Popular, 장소가 연결된 포스트만, 샵 포스트 제외 |

- 아이템(샵) 섹션은 넣지 않는다. 샵은 보류.

### 3.4 구독 관리 시트

- 검색
- **Pinned**: 구독 중인 토픽. 드래그로 순서 변경, 해제 버튼
- **전체 토픽**: L0 를 큰 제목(K-POP, K-CONTENT), L1 을 작은 제목(Boy Group, K-Drama …), 그 아래 L2 토픽 + 버튼
- 자식이 없는 L1 은 숨긴다

## 4. discover

### 4.1 위쪽 = 전국 범위

```
[검색바] [필터]
[ 구독 토픽 칩 … ]   ← 구독이 있을 때만, Hot 없음, 가로 스크롤
```

- 구독 토픽 칩: 누르면 그 토픽 필터가 걸리고, 다시 누르면 풀린다.
- 필터 시트: 조회용. 저장되지 않는다. 섹션 = 토픽 · SEEN IN · VIBE.
- 지역은 위쪽에 없다 (시트 제목에서 이동).

### 4.2 두 가지 모드

| 모드 | 조건 | 시트 | 지도 |
|---|---|---|---|
| **탐색 모드** | 검색어·토픽·태그 필터 없음 | 지도 위치를 따라 바뀌는 섹션 (4.3) | 사용자가 움직인 그대로 |
| **결과 모드** | 검색어 또는 토픽·태그 필터 | 전국 결과 목록 | 결과 전체에 맞춤. 움직이면 "Search this area" |

- 결과 모드 시트 제목: 걸린 조건 요약 (예: "BTS · 60 results", "BTS + Cafe"), 오른쪽에 "Stories on Home".
- 결과 모드에서도 카테고리 칩으로 좁힐 수 있다.

### 4.3 탐색 모드 시트

**제목** — `Now in Seoul ▾` / `In Seoul › Mapo-gu ▾`. 제목을 누르면 지역을 고르고, 지도가 그곳으로 날아간다. **지역은 필터가 아니라 이동이다.**

**단계** — 지도 줌에 따라 시도 단위 / 시군구 단위. 임계값은 구현하며 정한다 (예: 12 이하 시도, 13 이상 시군구).

**카테고리 칩** — 제목 아래. Food · Cafe · Bar · Attraction · Entertainment · Activity · Shop · Stay.
장소가 0곳인 카테고리는 숨긴다 (지도 전체 장소 기준, 필터에 따라 흔들리지 않게). 누르면 4.4.

**시도 단위 섹션**

1. Popular now
2. ReCreeshots in {시도}
3. Trending districts — 누르면 지도가 그 구로 확대
4. Events & festivals — 세로 포스터 카드 가로 캐러셀. 팬 이벤트 + TourAPI 축제
5. Journeys in {시도}
6. Attractions in {시도} — TourAPI 대표 명소

**시군구 단위 섹션**

1. Popular now
2. ReCreeshots nearby
3. Events & festivals
4. Journeys through here
5. Attractions in {시군구} — TourAPI

- Popular now · ReCreeshots · Events 에는 "See all" → 4.5 목록.
- 장소가 적은 구에서도 Attractions(TourAPI)는 거의 항상 채워져 빈 시트를 막는다.

### 4.4 카테고리 목록

- "Cafes in Mapo-gu" — **지금 보는 지역** 안에서.
- 정렬 기본 Nearest, Popular 선택 가능.
- 지도에는 그 카테고리 장소 핀만.
- 결과 모드에서 누르면 전국 결과 안에서 좁힌다 (예: BTS 카페 전국).

### 4.5 See all 목록

- 탭: Spots · ReCreeshots · Events. 관광지는 목록 없음.
- 범위 = 지금 보는 지역 + 걸린 필터.

### 4.6 지도 마커

- 장소 핀: 지금과 같음 (토픽 색).
- **이벤트 핀**: 모양이 다른 핀으로 같이 표시. 축제는 TourAPI 좌표(mapx/mapy), 좌표 없는 항목은 제외.
- **관광지**: 기본 표시 안 함. 관광지 카드를 누를 때만 그 한 곳을 잠깐 표시 + 상세 시트.

### 4.7 지도 위치 → 지역 판정

- 지도가 멈추고(idle) 약 0.5초 뒤 판정. 좌표를 반올림해 캐시.
- 판정 방법은 정찰 후 결정: (a) 카카오 coord2regioncode 를 서버 액션으로 감싸 캐시, (b) 화면 중심에서 가장 가까운 장소의 Area 로 역산.

## 5. 콘텐츠 규칙

### 5.1 인기 정렬 ("Popular now")

- 최근 7일 저장 수 순.
- 최근 7일 저장이 없으면 전체 기간 저장 수로 정렬하고, 이름을 "Popular" 로만 표시.
- 시간 표시("2h ago")는 쓰지 않는다.

### 5.2 빈 상태

- 데이터가 없는 섹션은 **통째로 숨긴다.** 제목만 남기지 않는다.
- 예외: 리크리샷 섹션이 비면 "Be the first to ReCreate this spot" CTA 카드(카메라 버튼)를 보여준다.

### 5.3 카드 배지

| 카드 | 규칙 |
|---|---|
| 목록 (3칸) | 대표 토픽 · SEEN IN 태그 · 대표 장소 타입 (순서 고정, 종류별 1개) |
| 홈 (2칸) | 앞 두 칸. 비는 칸은 토픽 → SEEN IN → 장소 타입 순으로 채움 |
| 상세 | 토픽 전부 → SEEN IN 전부 → VIBE → 장소 타입 전부 |

- VIBE 는 카드에 나오지 않는다.
- 링크는 L2 토픽 배지만.

### 5.4 카드를 누르면

- 포스트 카드 → 포스트 상세 (지도로 가지 않는다). 상세에 "See on map".
- 축제 카드 → 축제 상세 시트, 시트 안에 "근처 성지 보기"(그 지역 discover).

## 6. 구현 순서

**홈을 먼저, discover 를 나중에.** 브랜치를 나눈다.

### 홈 선행 작업
- TopicFollow 에 순서 칸 (마이그레이션)
- 인기 집계 쿼리 (최근 7일 저장)
- 한반도 윤곽 SVG 생성 스크립트 + 커밋
- `/` 리다이렉트, `/topics/<slug>` 리다이렉트

### discover 선행 작업
- 지도 카메라 상태 노출 (onIdle, 중심·줌·bounds)
- 위치 → 지역 판정 (4.7)
- 마커 종류 분기 (장소 · 이벤트 · 관광지 일시 표시)

## 7. 미정

- 시도/시군구 전환 줌 임계값
- 위치 판정 방법 (4.7 a/b)
- 구독 탭 최대 개수 (제한할지)
- 한반도 핫스팟 크기 규칙의 최소·최대
